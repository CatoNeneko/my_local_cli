# 上下文压缩与代码阅读

原来只是按用户轮次裁掉旧消息，避免超过请求字符预算。这次加入摘要：把旧轮次的目标、约束、文件、真实操作结果和待办保留下来，让模型继续工作时拥有简短记忆。

阅读顺序：`compaction.py` → `context_window.py` → `model_client.py` → `script.py` → `history.py`。

`context_view` 从完整历史寻找最新有效检查点。`covered_messages` 表示摘要覆盖的原列表位置，`prefix_hash` 是被覆盖原前缀的 SHA-256；原文变化或检查点格式有误时不使用摘要。检查点本身不重复作为普通聊天内容发送。

`plan_compaction` 找到用户轮次的边界。`tail` 是保留的最近轮次；工具请求和工具结果属于同一轮，不能拆开。默认保留两轮，必要时减少到一轮，但最新轮次总是保留。太大的最新附件不会被本功能偷偷截断。

`_summarize` 使用独立请求。`previous_summary` 是上次摘要，`records` 是本次新增旧记录。它们全部是待摘要的数据。每批受字符预算限制；长记录只有片段，标记 `truncated`。摘要请求没有工具，因此不能执行其中的命令。

`compact_messages` 在模型调用前后检查内存与磁盘历史是否一致；只有摘要有效且新请求预算可容纳时，才追加检查点并更新内存。生成、校验或写入失败时不启用新摘要。

`maybe_compact` 在主模型请求之前计算完整请求大小，达到阈值或轮次限制时调用压缩。摘要请求本身关闭自动压缩，避免递归。失败前缀记录在当前进程的有限缓存中，避免同一任务连续重试摘要；手动命令不受该缓存限制。

检查点和原历史放在同一个 JSONL，所以不需要为会话重命名再维护另一份摘要文件，也不会因为切换会话把摘要串给其他会话。导出包含元数据；清空当前会话同时清空检查点。

请求中的摘要以 assistant 历史数据注入，项目规则仍保留为 system。摘要不进入权限控制器，也不代替客户端保存的原始用户任务。权限审批、文件边界和沙箱规则不会因摘要文字变化。

边界：有损摘要、字符预算近似、最多六批与记录片段；不支持无损恢复到原生模型状态，也不宣称摘要免疫提示注入或永久保存所有细节。磁盘历史可供回查；当前没有针对多个 CLI 同时追加同一会话的完整事务隔离。
