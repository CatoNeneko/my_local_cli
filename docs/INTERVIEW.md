# 项目讲解与简历表述

可以把它描述为“Python 终端 AI 编程助手”，重点展示完整工具执行链，而不是声称复刻了 Codex / Claude Code。

## 简历表述示例

- 实现支持 Ollama 与 OpenAI 兼容 API 的终端 AI 编程助手，支持流式响应、JSONL 多会话恢复、上下文预算、自动/手动会话摘要及代码读取和搜索。
- 构建统一工具注册与执行入口，结合 JSON Schema、路径边界、diff 审查、冲突校验、Hooks 及审批审计；通过独立模型上下文审查普通文件变更，高风险请求保留人工确认。
- 基于 Linux bubblewrap 与 PTY 实现只读禁网执行、交互输入、超时及进程组清理；以独立进程运行并行子代理，通过受审查的修改建议协作，支持 stdio MCP 工具发现与调用。
- 完成 313 项本机测试及真实模型验证：测试失败后由子代理提出修复，独立审查自动批准，保持原测试不变并验证通过。

数字是本次真实验收记录，不是用户数、稳定性指标或在所有模型上的成功率。外部收费 API 尚未验证；GitHub CI 只跑普通测试，不能把本机全部集成测试说成已在 CI 运行。

## 面试时按这个顺序讲

1. 用户输入如何变成模型请求：`script.py` 保存用户消息，`agent.py` 进行有界工具循环，`context_window.py` 保留完整工具链，`compaction.py` 把旧轮次摘要为可恢复检查点，`model_client.py` 选择协议。
2. 模型提出工具调用后发生什么：统一入口先验证参数、路径和 Hook，再准备 diff / 命令。模型文本不是执行凭据。
3. 自动审批如何避免自己批自己：行动代理和审查请求的上下文分离；审查器无工具，输出固定 JSON；客户端硬规则优先，错误或不确定降级人工。
4. 沙箱保护什么：bubblewrap 的只读挂载、网络 namespace、环境清理及私有数据遮蔽；共享宿主内核，暂没有内存配额或完整 seccomp。
5. PTY 与普通 PIPE 有何区别：PTY 让子进程看到终端并支持控制终端、交互输入和 Ctrl+C；后台线程只负责收集输出，命令仍在沙箱中运行。
6. 多代理如何隔离：独立工作进程与配置快照，没有父聊天和直接写入工具；建议暂存，父代理申请应用后重新审查，并检查文件是否变化。
7. MCP 做什么：连接外部 stdio 服务，发现 JSON Schema 工具并注册到同一入口；并没有因此给外部 MCP 服务沙箱保障。
8. 如何证明完成：运行测试并展示真实失败、修改 diff、审批原因和通过输出，重启后展示会话恢复。明确当前没有跨进程后台任务恢复。

## 建议准备的演示

在外部临时项目启动 `ai-cli -C <项目> --no-mcp`，展示读取和搜索、普通修改的自动审查、沙箱测试、子代理建议、PTY 交互。再用 manual 模式展示拒绝写入后文件不变。MCP 单独演示连接授权与真实工具结果。

本项目以 AI 协作完成。应能解释实际代码、验证过程及权限边界，遇到尚未实现的功能直接说明；不把 AI 输出当成自己已经验证的技术结论。

## 浏览器扩展

通过独立 MCP 服务复用代理工具循环和审批入口，Playwright 控制 Chromium，临时 BrowserContext 管理 Cookie，页面快照用短正文和临时元素 ref 供模型定位。读取和操作刷新 ref，过期编号拒绝执行。截图保存为私有文件，未接入视觉模型。浏览器可联网，隔离范围与 pytest 的 bubblewrap 不同，不能声称所有 MCP 服务已被沙箱化。真实本地页面操作和 MCP 权限链经过测试；已用本机真实模型完成固定本地网页的打开、填写、点击、读取、截图验收；不代表所有网站都可自动操作。
